# Infrastructure decisions for A, B, K, L and M

**Baseline (5 November 2026).** The connected synthetic application at [`f188aecc`](https://github.com/OpenxIntelligence/open-intelligence/tree/f188aecc70f3415741dac0e7dd5bf3f2d9fd02a9) uses FastAPI, SQLAlchemy/Alembic and PostgreSQL 16, plus React, TypeScript and Vite. Keep those owners and their [backend artifact inventory](../../apps/api/dependency-license-inventory.json), [Python lock](../../apps/api/requirements.lock), [frontend lock](../../apps/web/package-lock.json) and rights gates. This section selects no new package, service, image, provider, model, dataset or deployment. It records upstream evidence and a decision on what to try **if** a requirement appears. Clinical identity, licensed data, production assurance and product distribution remain separate decisions.

| Decision | Compare | Recommendation and evidence to change it |
|---|---|---|
| Canonical API and store | FastAPI / Django / Flask; PostgreSQL / MariaDB / SQLite | Keep the mounted FastAPI routes, existing migrations, one PostgreSQL patient ledger and the separate SQLite reference's existing scope. A replacement must preserve schema history, permissions, original custody, audit receipts and retry semantics and show a measured advantage. |
| Work, cache and messaging | PostgreSQL work table / Celery / Dramatiq / Temporal; Valkey / Redis / Memcached; RabbitMQ / NATS JetStream / Kafka | No new service. If asynchronous dispatch is needed, first measure backlog age, completion latency, retry exhaustion and database lock waits on fictional jobs. Design short transactions with [`SKIP LOCKED`](https://www.postgresql.org/docs/16/sql-select.html) for queue consumers, unique idempotency keys, expiring leases, attempt limits and explicit recovery; this is a design option, not an implemented worker. Persistent replay across teams, complex timers or demonstrated contention can justify a separate experiment. Never store the grant of record in a cache. |

**How to read the rows.** Each project link identifies the official upstream; the version/commit link opens license bytes at the exact reviewed revision. For retained language/application libraries the source revision corresponds to the repository's version pin; the actual wheel/tarball/container is a separate boundary. Other commits are research snapshots, never an instruction to install a default branch or a release. A release link is an observed published tag/date (possibly a monorepo sibling), not evidence that the tag and reviewed development commit have identical terms. When a GitHub release was unavailable, the Git commit date is identified instead. Neither date proves a support contract, absence of vulnerabilities or future maintenance. The scope link is the reviewed build declaration or upstream technical evidence where available. It is **not** a resolved transitive SBOM.

**Decision and effort.** Retain means keep the existing synthetic use; evaluate means a bench candidate subject to the gate above; defer means no current need; reject means decline for the proposed role. L/M/H is estimated work to integrate and operate for the use described, not a benchmark. Like-role alternatives are in the decision table or the neighboring rows in the same group.

**Scores** are eight engineering triage marks, in order **technical fit / license compatibility / maintenance evidence / security / interoperability / performance / operational simplicity / long-term sustainability**. 2 is favorable, 1 conditional, 0 unfavorable, ? not established. Fit is relative to this scope (2 retain/evaluate, 1 optional, 0 replacement/rejection); licensing measures compatibility with the preferred policy at source level only (2 permissive primary grant, 1 separate obligations, 0 restrictive/mixed commercial terms); maintenance evidence is 2 for a tagged release observed in the last year, 1 for an active commit without a recent confirmed release, 0 for an archived upstream. Interoperability reflects compatibility with existing APIs or a documented portable contract. Simplicity reflects the estimated footprint (2/L, 1/M, 0/H). No CVE-free claim, workload performance score or long-term sustainability prediction is made without evidence; archive status is a negative sustainability signal.

**Commercial use and redistribution: read each row together with these source-level conditions.** MIT requires the copyright and permission notice with substantial copies; BSD-2-Clause and BSD-3-Clause retain notices, terms and disclaimers in source and binary distributions, with non-endorsement for BSD-3-Clause. Apache-2.0 permits commercial use and redistribution with license, applicable notices/NOTICE and changed-file markings; review its patent provisions. PostgreSQL permits use and redistribution with its prescribed notice and warranty paragraphs. CPython's historical grants, PSF terms, component notices and documentation examples have distinct terms. MPL-2.0, LGPL, GPL and AGPL permit commercial use under their own conditions: MPL has covered-file source obligations on distribution; LGPL requires assessing modified library source, linking/relinking and redistribution conditions; GPL requires assessing corresponding source and combined-work distribution; AGPL additionally covers remote interaction with a modified program. A service/process boundary is not a clearance. BUSL-1.1 is source-available with product-specific additional grants and change dates; mixed enterprise, third-party content and dataset terms remain package/path-specific. Any departure from the preferred license policy, public distribution, commercial hosted use, restricted data or unresolved upstream chain needs its own recorded decision. [Docker Desktop](https://docs.docker.com/subscription-billing/desktop-license/) is a separate subscription decision; [AG Grid Community](https://www.ag-grid.com/eula/community/) is distinct from Enterprise. No source-level determination below confers rights to operate or distribute the assembled product.

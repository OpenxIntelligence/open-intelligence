# AI platform architecture

The connected fictional H1 application prepares source context and preserves human-authored questions, comparisons and reports. It has no qualified model, inference server or autonomous chart writer. The [AI evaluation plan](AI_EVALUATION_PLAN.md) owns intended-use experiments; the [architecture decisions](ARCHITECTURE_DECISIONS.md) own branch reconciliation. The AI/evaluation owner (OI-011), domain owners and independent adjudicators (OI-014) own different decisions: whether a proposal can be produced, where it can be saved, and whether it helps the intended user.

## Contract for a future replaceable adapter

1. **Select a task and model server-side.** The registry entry must identify task/schema version, prompt and configuration hash, allowed input and output types, provider/endpoint, model revision and independently verified weight/tokenizer/adapter hashes, terms, permitted purpose, hardware profile, and evaluation receipt. Missing or revoked entries deny execution. Do not load untrusted model code at startup.
2. **Freeze the permitted source packet.** Bind actor, organization, patient, case, question and as-of revision; preserve original locators and exact content hashes. Treat retrieved text and pixels as untrusted data, never as instructions. Do not offer unrestricted SQL, filesystem, network or other-patient tools. No prompts or assets leave H1 under the current scope.
3. **Run outside the chart transaction.** A future adapter accepts the frozen packet, server-owned parameters, timeout, byte/token ceilings and cancellation; it returns structured claims and cited anchors or typed abstentions. Record time, resource use, retries and failures without storing sensitive payloads in operational logs. Do not retry a denied action through a fallback provider.
4. **Validate before retention or disclosure.** Check subject, schema, support and freshness; retain uncertainty, conflict and discarded-claim reasons. A re-run creates a new version; it never overwrites earlier reviewed claims. Correlate an output with the exact run. Count replay, simulated, failed and live runs separately. The [security plan](SECURITY_GOVERNANCE_PLAN.md) and [test protocol](TESTING_AND_EVALUATION.md) cover the two independent gates.

# Interoperability architecture

**Connected H1 at `f188aecc70f3`, 5 November 2026.** The integration boundary translates an authorized original into dependent projections. Open Intelligence owns patient/case identity, original custody, permissions and review. No external validator, archive, interface engine or terminology service becomes a clinical database.

## Ingress and egress contract

1. Resolve the external subject against a current [organization-qualified case binding](../../apps/api/src/oi_api/case_bindings.py). Never create a patient from a matching name; ambiguous bindings fail closed. Authorize preview, import, original retrieval and export independently.
2. Preview a bounded payload without a business write. A valid standard document outside the supported subset is **unsupported**, not necessarily invalid under the standard. Never dereference untrusted URLs or discard unknown fields while claiming a complete mapping.
3. On confirmed import, lock the case; verify source identity and any explicit current predecessor. Store native bytes/hash, format, source version and separately typed projections. A changed payload is not an exact retry. A FHIR source amendment at this owner is distinct from accepting an unsupported resource status of `corrected`.
4. Expose time, units, absence and local locators without deriving clinical meaning. For a future export, record recipient, permitted purpose, source versions and omissions; require current authority at artifact retrieval. A generated file is not confirmed delivery.

**Acceptance (OI-005, OI-006, OI-013):** reproduce preview-without-write, import/duplicate/amend/history, revoked original-read and active/revoked restore with [laboratory HTTP tests](../../apps/api/tests/test_laboratory_fhir_http.py) and [Compose verification](../../apps/api/tools/verify_fhir_laboratory_compose.py). Add cross-patient/cross-organization failures, unsupported language/profile, malformed identifiers and false-match cases for each expansion. For a proposed independent validator such as HAPI, capture exact profile/version/result separately from first-party acceptance. No new endpoint, terminology distribution or partner connection is authorized by this document.

# License and SBOM register

For the connected fictional H1 profile, the package registers below remain authoritative. The [candidate catalog](OPEN_SOURCE_TECHNOLOGY_CATALOG.md) records research evidence and proposed evaluations. It cannot grant adoption or distribution rights. Preserve the linked notices and exact artifacts when reviewing a change.

Container and OS layers, compiler/toolchains, built browser bundle composition, weights, clinical content, datasets and provider agreements require separate evidence and review. |

To verify the local installation, run both package gates, then follow [testing and evaluation](TESTING_AND_EVALUATION.md). A metadata-only run of the generator can detect drift in build inputs. The installed-gate mode also compares the two actual artifact receipts. Neither mode provides a CVE scan, signed provenance, legal acceptance or evidence of clinical validity.

For a proposed component, record the exact upstream project and commit/release, selected binary and digest, intended use, applicable SPDX expression/election, original license and notices, transitive/embedded components, plugins, native libraries and separately shipped assets. For content record agreement, version, permitted use and caching/redistribution/egress separately. Unknown terms block activation and require a named reviewer. Produce an image-layer inventory, vulnerability triage, release notices and distribution review before any institutional distribution.

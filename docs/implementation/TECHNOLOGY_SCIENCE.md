# Clinical NLP, scientific computing and research data: decision evidence

Reviewed 2026-11-05. Companion to the platform technology catalog (categories F, H, I and Part VI). This is a candidate inventory, not an installed-components SBOM. No package, checkpoint, dataset, external API integration, reference genome or container was installed or enabled for this review. No human data was accessed. A version below identifies the source examined, not a production pin. An upstream license is not authorization for a patient use.

## Foundation decision

1. **Retain the existing application and authorization boundary.** Define a local, typed request for candidate spans and source offsets, a separate artifact/worker interface for scientific jobs, and a reviewed evidence object for discovery outputs. Do not add a model server, scientific scheduler, service credentials or distributed registry to the core solely to support these interfaces.
2. **First AI experiment, when approved for implementation:** compare deterministic rules on authored fictional examples against a spaCy CPU baseline, then (separately) medspaCy for negation/sections. No weight files or terminology dictionary are needed by the first-party baseline. Do not auto-download a spaCy pipeline, UMLS linker, a Hub snapshot or a hosted judge. A claim remains unapproved even if multiple systems agree.
3. **First research worker, when a reproducible multi-step batch job is needed:** compare a local executor with Nextflow DSL2 (preferred candidate for heterogeneous CLI pipelines) and Snakemake (alternative for a small Python-oriented DAG). Represent nf-core as workflow authors, not an alternative engine. Start without Galaxy's second identity/workspace environment. Start a future synthetic fixture with read QC, a reference hash, alignment and QC on a small artificial sequence; fastp, minimap2, SAMtools/HTSlib are independent evaluation candidates. Choose an aligner for read type and task; minimap2 is not a validated substitute for a short-read somatic caller. No live cluster, ontology or human reference required by the fixture.
4. **Discovery should produce hypotheses with evidence and a falsification experiment.** Start by evaluating RDKit descriptors, Biotite parsers and a locally rendered Mol* structure on independently cleared inputs. Do not rank clinical therapies from a score, docking pose, network centrality or predicted peptide binding. No auto-promotion into patient facts, recommendations or order entry.

## Reading the inventory

Each project links its exact upstream tag/commit, inspected license or package declaration, and a manifest or build source. Dates are upstream publication or commit dates: one recent release is activity evidence, not a guarantee of sustainable maintenance. A SHA is a source snapshot, which may be a development version. Candidate comparison is advisory: `evaluate` means a future isolated synthetic comparison; `defer` means no integration; `reject core` means the component/terms are unsuitable for the distributed core as evaluated. H/M/L denotes engineering effort, not clinical readiness.

Commercial-use and redistribution legend (applies to the named source only):
- MIT: commercial use and redistribution allowed; retain copyright and permission notice. BSD-2/3-Clause: preserve copyright, conditions and disclaimers on source and binary redistribution; BSD-3 also limits endorsement. Apache-2.0: commercial use and distribution allowed subject to the license, attribution/NOTICE where applicable and marking modified files; includes a patent grant subject to its terms.
- A GPL/LGPL label does **not** mean commercial use is prohibited. Copyleft obligations depend on the files, build, linking and delivery; review source provision, license notices and, for LGPL, modification/relinking rights. No such distribution approved. Artistic, custom, mixed and file-level terms require a separate decision. The applicable license text prevails; a bare “GPL v3” license copy does not by itself establish an application grant of “or later.”
- Component notices/manifests were sampled. Optional dependencies, plugins, GPU drivers/toolkits, OS images, tool binaries, vocabularies, reference databases, weights and training corpora are separately controlled. No resolved transitive license tree, complete build SBOM, vulnerability scan or clinical performance result exists for these candidates. Release review must resolve exact wheels/archives/containers, lock by digest, inspect vendored notices/asset grants, scan advisories and publish a scoped SBOM before use. A missing right means **hold**, not permission.
- Provisional evaluation dimensions: **fit** is the named responsibility and competing choice; **license** is the listed grant and exceptions; **maintenance** is the dated release or commit; **security** is the per-family threat below plus specific gates; **interoperability** is the exchange format/contract below; **performance** is unmeasured throughout; **operational complexity** is the per-row effort; **sustainability** requires upstream support/security policy and a reproducible exit test before adoption. Do not make a quantitative ranking from unknowns.

| Family | Security, interoperability and performance questions to resolve before selection |
|---|---|
| Clinical NLP and evaluation | Independently match spans to UTF-8-safe source offsets; handle negation, temporality, hypothetical and family history; deny unauthorized retrieval, tools and network destinations. Judge/reference models must receive only authorized content. Track per-site/type critical misses and unsupported claims, inter-reviewer agreement, abstention coverage, latency, memory and throughput at concurrent load. A RAG quality score cannot sign a clinical finding. |
| DNA | Compare FASTQ → sorted BAM/CRAM → VCF/BCF against known synthetic alleles; instrument mapping rate, depth, strand/allele balance, reference build/contig and variant normalization. Distinguish tumor/normal, small variants, CNV, SV and fusions. Incorrect reference or sample identity must fail. Bound parser memory/decompression, threads, wall time, temporary files and untrusted CLI parameters. |
| RNA and single-cell | FASTQ → counts keyed by stable gene/transcript IDs, annotation version, cell barcodes and sample IDs. Compare strandedness, multimapping, duplication, pairing, library chemistry and reference annotation; track QC, cell recovery, batch effects, doublets and rare-cell sensitivity. Check memory per million reads/cells and out-of-core behavior. Counts/normalized counts/inferred cell states are distinct artifacts. |
| Multi-omics | Join assay identifiers through an explicit specimen/patient mapping; verify feature axes, missingness, train/test leakage, batch effects and stability by site and resampling. Treat H5AD/R serialized files as untrusted inputs; prefer constrained readers; retain exact R/Bioconductor or Python lock, seed and precision policy. No causal claim from factors, clustering or pathway scores. |
| Workflow engines | Engine consumes an immutable workflow, typed parameters and a local job manifest; outputs content-addressed artifacts and lineage. Compare no-network rerun, injected worker failure, bounded retry, cancel/resume, concurrent jobs, secret handling and cost. Do not pass user-supplied Groovy, Python, shell, arbitrary namespace/URI or Docker socket to a worker. Engines must not authorize access to clinical tables. |
| Discovery | Record structure/sequence accession and revision, chain/assembly, preparation, protonation, stereochemistry, force field/solver, positive/negative controls and uncertainty. Enforce viewer URL allowlist and offline IO; treat PDB/SDF/mmCIF/SMILES as untrusted. Blind predictions against held-out chemical scaffolds, proteins or cohorts and experimental endpoints. Do not infer potency, toxicity or presentation from a single score. |

## Reproducibility, acceptance and clinical separation

A grant is scoped to resource, version, owner, project/purpose, user/institution, consent/use code, destination and time. Resolve it **before** queueing, before a worker reads bytes, and before publishing any output (including derived models). Unknown grants deny. On expiry/revocation stop new reads, invalidate cached tokens and isolate partial jobs. A disposal manifest must include worker disks, stored outputs, embeddings, indexes, model parameters, exports and recoverable backups; track backup expiration, restore-time tombstones and deletion attestations without storing raw patient text in the audit log.

Minimum future run envelope (design contract, not a claim of implementation):

| Phase | Required immutable evidence |
|---|---|
| Authorization and inputs | Tenant and pseudonymous project/sample keys; user/service identity; authorized purpose, decision ID, policy and consent/DUA version, expiration and permitted processors; source/accession/version, internal object ID, file size, format and SHA-256 for each input. Freeze cohort selection and supplement metadata. |
| Execution | Run + attempt IDs, parent/dependency run IDs, workflow source commit/tree hash, engine/pipeline/tool versions, immutable container digest **and** architecture, software SBOM digest; reference species/assembly/release, FASTA/index/GTF hashes or explicit not-applicable; parameters/defaults, input order, command template, seeds, thread counts, hardware/device/driver, precision, relevant environment, UTC start/finish. |
| Results | QC metrics/threshold version, pass/fail/indeterminate, output objects/types/hashes, restricted stdout/stderr references with redaction, termination/error class, retries/resources and partial-output disposal. Preserve raw and normalized values and allowlisted transformations. |
| Reproduction and review | Rerun offline in a clean environment on approved inputs; compare hashes for deterministic outputs and prespecified absolute/relative tolerances and invariants for stochastic or floating-point outputs. Store both run IDs, deviations, clinical/scientific reviewer and reviewed status. No unreviewed output may update the canonical EHR. |

First evaluation fixtures: authored fictional notes with negated/hypothetical/family-history mentions and explicit source segments; tiny artificial DNA/RNA read/reference pairs with known variants and splice junctions; two manufactured cell count matrices with deliberately permuted features and sample IDs; known stereoisomers for descriptor consistency; blinded independent experimental measures for any later docking/ADMET claim. A fixture verifies the pipeline, not clinical performance. Define independent, specialist-adjudicated cohorts, critical-error taxonomy, subgroup/temporal splits, release thresholds, rollback and post-release monitoring before a clinical claim. No benchmark numbers or adverse-event rates are asserted.

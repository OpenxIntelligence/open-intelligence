# Bioinformatics architecture and scientific data governance

**Decision at 2026-11-05: keep the existing case, source, rights, and question owners.** Keep the clinical API free of scientific runtimes. Stage 7 is a proposed extension: first register one fictional assay with verifiable inputs and produce a reproducible, reviewable measurement. No sequencer, bioinformatics engine, reference genome, public patient dataset, image, or pretrained asset was installed or downloaded in this review.

## First scientific profile: proposing a run

1. An investigator links a question to the exact case, episode, specimen/aliquot, assay and source version. Distinguish tumor from matched normal, tissue from liquid, biological from technical replicate and collection from report/receipt time. Keep unknown identity or consent explicit. Resolve research authority **before** opening an artifact.
2. The run planner validates an allowlisted, versioned workflow and schemas. Only opaque artifact IDs inside the authorized scope are resolvable. A trusted worker stages verified bytes in an isolated workspace with no network by default, read-only inputs, bounded CPU/RAM/disk/time, short-lived grants and an output allowlist. Arbitrary shell, remote plugins, contig lookups and analyst-supplied executable code are outside the initial profile.
3. Worker reports attempts and QC to the existing job/evidence contracts. The server verifies hashes and checks current authority at publication, read, export and retry; a retry of the same intent cannot attach a result twice. Classify output as calculated/research; failed, insufficient, not assessed, no call and negative are distinct. A scientist may judge a run technically interpretable; this is never a clinician-signed interpretation.
4. A source/reference/software correction, permission restriction or withdrawal opens a reassessment for dependent run versions only. Retain authorized provenance and prior review history; restrict prior content where access changed. Deletion and backup erasure policy can require removal of bytes; immutable evidence is not permission to retain prohibited material.

**Receipt contract (proposed, not a current endpoint).** Required for successes and failures:

| Field group | Minimum needed for replay or investigation |
|---|---|
| Scope and time | tenant, case, question, authorized purpose, requester and role, as-known-at snapshot, planned/queued/started/finished UTC, attempt ID, parent attempt and revision; no identifiers in platform logs |
| Inputs and controls | source and artifact versions; SHA-256 and byte length of original and transformed files; ordered sample sheet, assay, pairing, tissue/time, library chemistry, controls, chain of custody, independently authored fixture provenance |
| Reference and data | assembly/accession **and** exact FASTA/contig/index checksums, annotation provider/release and GTF digest, chromosome naming policy; dataset version/accession, release date, access class, rights record version. Use explicit “not applicable with reason” for a reference-free workflow. |
| Software and settings | pipeline repo/commit, module code revision, resolved tool versions, package lock and SBOM, immutable OCI manifest digest + platform, runtime, OS/arch, resource limits, command/parameter file with defaults, compiled flags, random seeds and CPU/GPU/driver where relevant |
| Result and replay | schema/version, checksums and units of **all** declared outputs, read counts/filter thresholds and QC decisions, transforms/losses, exit code and sanitized error category; record unproduced outputs, cancellation and limits. Freeze comparator, expected invariants and numeric tolerances; bitwise vs statistical reproducibility is declared before testing. |

Use a miniature invented reference (e.g. contig `SYN1`, not a renamed human sequence) with paired synthetic reads or a manufactured count matrix. Shuffling input lines, multiallelic normalization and version changes must not erase original coordinates. Treat ambiguous liftover, strand, allele orientation and transcript choices as unresolved. Preserve original and transformed identifiers together.

**Preferred experiment:** For bulk RNA, use Nextflow plus one frozen nf-core/rnaseq profile in an isolated batch worker; permit only the reviewed subset of modules. [3.27.0 config](https://github.com/nf-core/rnaseq/blob/a1fcdddd3b826fe46eb46f0479f2ff8a7815af05/nextflow.config) specifies a minimum Nextflow 25.10.4; 26.10.5 satisfies that declared floor, but the pairing has not been executed here. For one tiny offline parser, a direct process may be sufficient; adopt a workflow engine only when checkpoint/retry, trace completeness or multi-step replay demonstrably justifies its maintenance. Do not embed Galaxy or a second scheduler in H1. Prefer AnnData and Scanpy for an independently justified single-cell track, and use the [Bioconductor release and per-package policy](https://contributions.bioconductor.org/license.html) for R-only methods; Bioconductor is an ecosystem, not one license or one dependency.

**Comparison before selection.** Test the same synthetic RNA question across a direct baseline, Nextflow and Snakemake; Galaxy only when interactive editing is a requirement. Measure wall time and peak RSS/disk at fixed read count/core count, cold and warm cache, failed-step recovery, human setup minutes, lock completeness, logged parameter fidelity and clean rebuild. For aligner/quantifier comparisons, predeclare which results must agree (input count, assay identity, direction of an engineered change) and which may legitimately differ (multi-map assignment, abundance estimate). For single-cell QC measure proportion and identity of known synthetic failures retained; clustering stability is not cell-type truth. For multi-omics use the specimen/time join as the first acceptance result: no inference on unmatched or unconsented aliquots. Proteomic intensities, CNV segments, methylation fractions and RNA counts need separate units, coverage, normalization and missingness; no universal cross-modal fold change.

**Maintenance and distribution gate.** The upstream release histories for [Nextflow](https://github.com/nextflow-io/nextflow/releases/tag/v26.10.5), [nf-core/rnaseq](https://github.com/nf-core/rnaseq/releases/tag/3.27.0), [Snakemake](https://github.com/snakemake/snakemake/releases/tag/v9.27.1) and [Scanpy](https://github.com/scverse/scanpy/releases/tag/1.12.5) provide dated release records. These are candidates, not runtime pins. Earlier listed versions provide bounded comparisons, not assurances of current support. Require per-image multiarch digest, resolved lock, notices, user-facing source offers if applicable, security/support review, offline reference provisioning, cost envelope and a second-person replay before adoption. ## Data admission register — Part VI

**Current project decision for every row: no dataset acquisition, redistribution, model training, embedding, external inference or provider transfer was approved or performed here.** The table distinguishes the upstream route from what this project may do. “Public” describes availability; it does not authorize a participant-level join, replicate a real individual's record or grant rights to linked articles. Independently authored synthetic cases remain the only patient engineering inputs. Synthea itself is an optional generator assessment, not a replacement for the existing challenge cases.

**Controls that apply to every entry.** Before acquisition the rights reviewer records the precise release/file/accession, publisher and original URL, retrieval date, license/terms version and snapshot hash, consent or other authorized basis and purpose, restrictions on derivatives, accountable custodian, and actors authorized for store/display/redistribute/train/provider transfer. No missing consent or permission defaults to yes. The owner assigns a review/expiry date and actual retention/deletion trigger for each original, cache, backup, embedding, checkpoint, export and report, subject to the applicable agreement. **Absent a signed-off retention/deletion schedule, the retention period for new local data is zero: do not acquire.** On withdrawal/expiry stop access/jobs, revoke descendants, purge where required, expire backup/key copies on a tested schedule, and record destruction without retaining disallowed content. Public bibliographic identifiers may survive only where permitted. These are design controls, not assertions that a particular licensor mandates a universal time limit.

Staging and production configurations with institutionally accepted security, operational ownership and recovery objectives remain open.

## Patient traffic

The process-local `OI_API_PATIENT_COMMANDS_PER_MINUTE` value controls initial burst and steady refill. The local default is 240 commands, replenished at four per second. A refusal returns HTTP 429 with an integer retry delay; preserve command identity on retry. Access checks still apply to admitted calls. The setting counts POST-based preparation as well as mutations. A busy caller can consume the entire process budget. Multiple processes and restarts have independent budgets. Collect a representative workload and availability requirements before setting institutional quotas or choosing a shared counter.

This clinical candidate requires `0023_ehr_lab_ownership_join`; main at `f188aecc` requires `0018_laboratory_questions`. Match the application and migration tree. The note-version POST preserves its 242,000-byte envelope for escaped Unicode.

Use the existing timeout/error boundaries to observe job state, API availability, saturation and recovery duration. A proposed metrics pipeline should emit fixed operation IDs, status classes, bounded latency buckets and retry counts; exclude raw paths, subject IDs, tokens, request bodies, prompts and SQL. Test telemetry with canary input and inspect what is actually exported. On a failed deployment, preserve logs within policy, stop traffic, identify the last known compatible application/schema pair and restore a copy before deciding any downgrade. Do not reverse a populated migration merely to make readiness green.

# H1 second-opinion preparation

## Purpose
Turn the existing authorized case, originals, saved questions and recorded follow-up work into a patient-facing second-opinion preparation checkpoint without inventing a referral, recipient, clinical recommendation or transmission channel.

## Boundaries
- Reuse the current patient/case, source-index, question-history and follow-through owners.
- No new API, persistence, dependency, model, specialist directory or external action.
- A successful summary means only that currently loaded preparation inputs are organized.
- Source reassessment outranks apparent readiness.
- Unchecked or unavailable reads never become zero or complete.
- Recipient verification, deliberate record selection, disclosure authorization, transmission, acknowledgment and appointment confirmation remain future explicit workflows.

## Acceptance
1. The card is absent without one authorized active patient/case.
2. Records and question history must each have a successful exact-case read before readiness can be assessed.
3. No current source means records are missing; no current question means a focused question is needed.
4. Any source-reassessment question blocks current preparation even if another question is current.
5. Follow-up ownership is descriptive only and does not determine clinical readiness.
6. Browser acceptance after a real source amendment shows the preparation as needing reassessment.
7. The UI explicitly says it does not create a referral, send records, establish eligibility or confirm an appointment.
8. Existing source/question/task permission and stale-response behavior remains unchanged.

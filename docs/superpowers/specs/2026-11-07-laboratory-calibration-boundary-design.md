# Reserved calibration data for laboratory experiments

## Intent and current evidence

Continue OI-011 and OI-018 through the existing offline laboratory registry. At
parent revision `539705d0741e8192c027c250a2bb016b13d2dca9`, the registry already
supports immutable recipes, a bounded local executor, an exact-source memory
control, validation-based selection, cancellation, lineage and comparison.
The 63 focused checks passed again before this change on Python 3.12.14.
Before delivery, the implementation was reconciled onto parent revision
`f43df38fe230f7dcd05042baf6d7f7b549dd24f7`, retaining its additional budget and
atomic-persistence corrections. The combined focused selection passed 77 checks.

The next capability is a separately reserved calibration information role. The
current adapters perform structured laboratory extraction and supply no qualified
probability or conformal score. This increment therefore reserves data for a later
postprocessor; it does not fit a calibrator or establish coverage, uncertainty
quality, clinical performance, or an unseen final evaluation.

## Approaches considered

1. Add `calibration` to the existing `SPLITS` tuple. Rejected: that tuple also
   defines historical implicit run scope and serialized score keys.
2. Add a versioned dataset contract within the current owner. Selected for this
   bounded implementation: explicit new semantics, historical byte compatibility,
   and no new persistence or domain owner.
3. Add conformal computation now. Deferred: an appropriate uncertainty-bearing
   target, score, calibration procedure and sampling assumptions are not defined
   for either current adapter.

## Behavior

- Preserve `oi.synthetic-laboratory-evaluation/1` with exactly train, validation,
  and test. Its implicit run scope and score serialization remain unchanged.
- Add `oi.synthetic-laboratory-evaluation/2` with train, validation, calibration,
  and test. V2 runs always persist their resolved `evaluated_splits` explicitly.
- Keep an absent `evaluated_splits` field meaningful only for v1. V2 may not rely
  on that historical default. Propagate the dataset contract into run, score and
  training-export records.
- Preserve patient, source-family and source-hash split locks across dataset
  names, versions and amendments. A failed freeze is atomic. Only train rows may
  be marked training eligible.
- Keep the executor's existing positive allowlists: eligible reviewed train
  examples for fitting, validation inputs for inference and selection.
  Calibration cases and reviews are not worker inputs or selection evidence.
- New v2 plans and final receipts explicitly record
  `calibration_sent_to_worker=false`, `calibration_scored=false`, and
  `calibration_performed=false`. Historical plans and receipts are not rewritten.
- Preserve calibration source identities in existing dataset lineage. Generic
  manual baseline/scoring can inspect calibration cases with an explicit v2 run
  scope. That operation is not fitting a calibrator or establishing protected
  access. Existing local-administrator and repeated-evaluation limitations remain.

## Construction boundaries

Use the existing `laboratory_evaluation.py` and `laboratory_experiments.py` owners.
No new database, schema migration, API route, UI, dependency, model, provider,
patient/source authority, clinical action or deployment is introduced.
Only independently authored fictional fixtures are used. Existing public practice
fixtures remain v1; they are not relabeled as an unseen calibration population.

Source changes invalidate previously frozen, unexecuted plans by the existing
code-identity check. Finished historical results remain readable and replayable
as stored evidence; compatibility does not mean executing old plans under new code.

## Acceptance

Require real subprocess evidence of exclusion, selection unchanged by changes
only to reserved calibration data, manual calibration-only scoring with correct
denominators, cross-role rejection with rollback, and exact v1 run/score retries
against canonical payloads generated by the parent implementation. Keep the
existing failure, cancellation, lineage and comparison checks.

The original v1 fixture records identify their producing revision. They establish
serialization compatibility only, not independent clinical reference quality.

## Research connection

[Angelopoulos and Bates](https://arxiv.org/abs/2107.07511) motivate a separate
calibration role when an appropriate conformal procedure is introduced. This
engineering boundary alone supplies none of that procedure's statistical
guarantees. Future work must define the task, nonconformity score, independent
sampling unit, exchangeability or alternative assumptions, calibration population,
coverage/risk scope, and evaluation of set usefulness and review burden.

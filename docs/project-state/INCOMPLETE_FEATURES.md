## Required status vocabulary

| Status | Meaning in this assessment |
|---|---|
| Fully implemented and tested | Defined bounded behavior has execution evidence at a named commit; says nothing about broader product/clinical completion. |
| Implemented but not adequately tested | Code exists, but relevant acceptance, adversarial or integrated execution is absent. |
| Partially implemented | Some of the required workflow works; listed steps or qualifications remain. |
| Designed but not implemented | A concrete design or contract exists without verified executable completion. |
| Proposed but not approved | An option or requirement awaits a recorded decision. |
| Missing | No implementation was established in the inspected scope. This is not an assertion that every unreviewed branch lacks one. |
| Broken | Observed behavior fails its required contract. A suspicion or old audit finding alone is not labeled broken. |
| Blocked by external dependencies | Progress requires a real outside dependency such as provider access, qualified authority, source rights or operational approval. |

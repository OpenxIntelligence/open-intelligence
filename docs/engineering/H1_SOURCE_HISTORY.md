# Receipt-time source history

This OI-009 increment builds on connected foundation `2e37d7579f3d748dfe2918a1ec4d02872e0e625c` (PR #602). It adds an operational historical source-membership view through the existing PostgreSQL source owner, patient API and Records workspace. It introduces no tables, migrations, dependencies, alternate source store or new permission action.

## Behavior and boundary

`GET /v1/patients/{patient_id}/cases/{case_id}/source-history?received_through=<RFC3339>` selects the highest received version per document at or before an inclusive receipt cutoff. Timezone-bearing inputs are normalized to UTC without losing PostgreSQL microseconds. Ambiguous, invalid, over-precision and future cutoffs are rejected. Out-of-order imports use platform receipt time, never their earlier event or issue dates. Nonmonotonic receipt chronology within a document fails closed.

The result identifies the selected original by source ID, document, version, SHA-256, specimen and dates. It omits today's mutable current/superseded labels, current assertions and future membership. The source owner validates canonical originals under its existing patient/case locks, prepares and encodes the response, checks current authority, records a reference-only disclosure receipt, rechecks authority and commits. Audit digests describe the returned historical membership and cutoff. Failed authorization, preparation or audit withholds the result; denial creates no receipt.

Records offers the existing receipt times and opens each selected exact original through the separately authorized original-read endpoint. Original opening is a present-day access operation, not historical permission replay. Selection changes, record refreshes, case/patient changes, navigation and disconnect discard or abort pending historical responses. The browser verifies membership against its current authorized source index, including microsecond boundaries; incompatible responses require refreshing records.

This is source metadata history for structured report and supported laboratory source versions. It is **not** a historical clinical World Model, assertion reconstruction, clinician-knowledge timeline, prior grant reconstruction or point-in-time reconstruction of manual annotations, image assets, hypotheses, questions, review conclusions or external evidence. Current index integrity must remain valid even for an earlier cutoff. UI time choices come from already-loaded authorized sources; arbitrary valid cutoffs are available through the API. The complete longitudinal platform remains unfinished.

## Verification

The change adds real PostgreSQL/HTTP regressions for amendments, late older reports, exact originals, API restart, independent original-read permission, wrong case/organization, invalid cutoffs, authority changes during response preparation and after audit insertion, and audit failure. Existing Compose verification additionally checks exact historical membership after API/database restart and dump/restore, current permission denial and restored binding revocation, while comparing full durable state and returned audit receipts. The existing browser journey checks historical version selection, original bytes, focus return, mobile/desktop reflow and refresh invalidation.

Local validation before publication: 749 client tests passed; frontend production build passed; static engine ownership and inherited synthetic-data checks passed. 12 timestamp-boundary and API-contract checks passed locally; three PostgreSQL history tests were skipped. The broader API suite cannot complete in this container: PostgreSQL is unavailable and Unix socket setup is restricted. Its first run had 617 database skips, 75 environment errors and one OpenAPI route-inventory failure; the inventory was corrected to include the new endpoint. These are not represented as a passing full API run. Exact-head hosted PostgreSQL, browser and recovery results are tracked on draft PR #617. The initial browser attempt correctly denied an original read because its fixture lacked the independent grant; the journey now explicitly checks that denial before authorizing and verifying the original. Receipt-time HTTP and source recovery checks run before the broad hosted API regression for earlier failure feedback.

Next construction dependency: historical source-reported assertion and observation projection must retain exact original anchors and separate receipt time from clinical event time before it can be integrated into a broader historical Patient World Model.
